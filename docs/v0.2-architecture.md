# Writer Room v0.2 架构升级草案

## 目标

把系统从“Scene 功能流水线”升级为“Chapter 导演制小说工坊”。

## 新增模块

- **Briefing capability**：对话式立项 / 任务澄清，负责准入判断
- **Bootstrap capability**：把对话摘要转成 `project.yaml` / `runtime.yaml`
- **Orchestrator**：常驻中心调度、状态机、返工路由
- **Prose Director**：把 beats 转成小说表达方案
- **Chapter Assembly**：组装整章并补过桥段、呼吸段、余波段
- **Novel-Novelize Skill**：承接 prose brief、小说化扩写、抗摘要化检查

## 新工作流

```text
作者自然语言输入
→ intake summary
→ project.yaml / runtime.yaml
→ 章纲
→ scene beats
→ prose brief
→ scene skeleton
→ prose expansion
→ scene critic
→ chapter assembly
→ chapter critic
→ archive
```

## 状态机摘要

### Intake 准入态

| 状态 | 含义 | 下一个默认动作 |
|------|------|----------------|
| idea_raw | 想法仍模糊 | briefing capability 继续澄清 |
| brief_partial | 已有部分约束 | briefing capability 补关键缺口 |
| brief_ready | 信息足够进入中台 | bootstrap capability 生成状态契约 |
| in_orchestrator | 已正式进入中台 | Orchestrator 接管 |

### Execution 执行态

| 状态 | 含义 | 下一个默认动作 |
|------|------|----------------|
| planned | 章纲已建立 | Scene Planner 生成 beats |
| beat_ready | beats 完成 | Prose Director 生成 prose brief |
| prose_ready | prose brief 完成 | Writer 写 skeleton |
| drafting | 正在写作 | Writer 执行 expansion |
| review_failed_minor | 小问题 | Writer 局部修文 |
| review_failed_major | 大问题 | Writer 重写 scene / 补 bridge |
| replan_required | 规划问题 | Scene Planner 或 Architect 重规划 |
| rollback_requested | Human 指定回退重做 | Orchestrator 冻结后续任务并回退到目标 stage |
| rhythm_revise_pending | 待执行节奏微调 | Writer 仅调整情绪波形/桥接密度/段落节奏 |
| rhythm_revise_review | 节奏修订评审中 | Critic 复审 `emotion_wave_health` 与章节连贯性 |
| simulation_pending | 待执行模拟推演 | Scene Planner 发起对话/事件模拟 |
| simulation_review | 模拟结果评审中 | Orchestrator 决策是否回写 plan |
| scene_approved | 单 scene 通过 | Orchestrator 组章 |
| chapter_assembling | 章级组装 | Critic 做 chapter-level 审查 |
| chapter_approved | 本章通过 | Archivist 归档 |
| archived | 已归档 | 进入下一章 |

## State Contract 约束

推荐拆分为两个文件：

- `projects/{{novel_id}}/project.yaml`：长期、慢变信息。
- `projects/{{novel_id}}/workspace/runtime/runtime.yaml`：当前叙事状态、任务要求、运行时调度控制。

Orchestrator 的最小决策输入：

```yaml
runtime:
  stage: drafting
  auto_flow: true
  allow_replan: true
  allow_simulation: true
  next_action_hint: call_writer
```

Writer / Critic 的最小文本约束输入：

```yaml
narrative_state:
  pov_character: 林渊
  emotional_target: 压迫+试探
  narrative_function: 关系试探+信息误导

task:
  task_type: scene_generation
  requirements:
    min_length: 900
    must_include:
      - 环境压迫感
      - 内心误判
```

Human 回退请求建议附加字段：

```yaml
runtime:
  rollback:
    requested: true
    trigger: human
    target_chapter: 5
    target_scene: 2
    target_stage: beat_ready
    reason: 角色动机不成立，需要重做 beats
```

模拟推演任务建议附加字段：

```yaml
task:
  task_type: simulation
  simulation:
    mode: dialogue # dialogue | event
    scope: scene-05-02
    purpose: 验证冲突升级链条
    max_turns: 12
    output_ref: simulations/dialogue-scene-05-02.md
```


## 是否要做成新的 Room Agents？

当前建议：**重要，但先不要默认升格。**

更稳妥的做法是先把 `briefing` / `bootstrap` 当成前台能力或 Orchestrator 之前的子流程，实现后再跑 workload tests。若以下指标通过，再考虑变成正式 Room Agents：

- intake 完整率提升
- 误启动率下降
- 人工补问轮次下降
- 对总延迟和 token 成本的增加在可接受范围内
- 与 Orchestrator / Architect 的职责边界稳定
